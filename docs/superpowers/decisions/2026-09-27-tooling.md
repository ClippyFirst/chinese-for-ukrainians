# Tooling decision — Chinese converter

Date: 2026-09-27

## Decision

Use a framework-free Vite application with plain modern JavaScript and CSS. Use Node's built-in test runner for unit/integration tests and Playwright Test for browser acceptance tests.

Use `pinyin-pro` 3.29.4 as the Mandarin pronunciation engine and `@pinyin-pro/data` 3.29.4 for its official Traditional-character dictionary. The application calls `addTraditionalDict()` once during startup and passes `traditional: true` for explicitly Traditional input.

## Why

- `pinyin-pro` provides phrase-aware conversion, polyphonic handling, segmentation, tone-number output, and browser support. Version 3.29.4 is MIT licensed.
- Its documented `addTraditionalDict` API exists specifically to improve Traditional-character recognition and is available from v3.28.0+.
- Vite is sufficient for a small static frontend and produces optimized static assets.
- Node >=22.12.0 provides the built-in test runner needed by the project, avoiding a second unit-test runtime.
- Playwright Test provides cross-browser end-to-end testing for Chromium, Firefox, and WebKit.

## Important limitation

`pinyin-pro` is a pronunciation dependency, not the Ukrainian transcription source. The Ukrainian systems remain entirely sourced from `zh-in-ua.csv` and are rendered by our own mapping layer.

## Rejected alternatives

- A browser CDN build: rejected because the MVP must work offline after the static assets are loaded and must not transmit user text.
- A framework such as React/Vue: rejected because it adds an abstraction layer without improving this single-screen utility.
- Automatic Traditional→Simplified conversion before pronunciation: rejected because it would hide script handling inside a lossy normalization step. The selected engine has a documented Traditional dictionary path instead.
